# Спецификация Markdown Publication HTML Builder

## Назначение

`build-html.js` преобразует папку с Markdown-публикацией в папку со статической HTML-публикацией. Сгенерированные страницы можно открывать напрямую из файловой системы, без dev-сервера.

## Командный интерфейс

```bash
node build-html.js <source-dir> [output-dir]
npm run build -- <source-dir> [output-dir]
npm run serve
```

- `<source-dir>` обязателен и должен указывать на папку.
- `[output-dir]` опционален.
- Если `[output-dir]` не указан, скрипт пишет в `<source-dir>-html`.
- Папка результата удаляется и создается заново при каждой сборке.
- `npm run serve` запускает локальный HTTP-сервер на порту 3000 для просмотра папки `the-fire-kasina-markdown-html`.

## Файлы программы

- `build-html.js`: Node.js-скрипт сборки и логика конвертации Markdown.
- `serve.js`: Node.js-скрипт для запуска локального HTTP-сервера для просмотра сгенерированного HTML.
- `template.html`: общий HTML-шаблон страницы.
- `nav.html`: шаблон правой боковой навигации.
- `main.css`: исходный CSS темы и основной оболочки, который копируется в результат как `main.css`.
- `nav.css`: исходный CSS боковой навигации, который копируется в результат как `nav.css`.
- `article.css`: исходный CSS оформления текста статьи, который копируется в результат как `article.css`.
- `publication.js`: исходный JavaScript оболочки, навигации, темы и режимов чтения, который копируется в результат как `publication.js`.
- `package.json`: npm-скрипты и зависимость `markdown-it`.

## Правила входных данных

- Все `.md` файлы внутри `<source-dir>` конвертируются рекурсивно.
- Все не-Markdown файлы копируются рекурсивно без изменений.
- `index.md`, если он есть, сортируется первым и становится `index.html`.
- Заголовок страницы и подпись в навигации берутся из первого Markdown H1.
- Если H1 нет, используется имя файла без расширения.

## Переписывание ссылок

Скрипт переписывает только локальные ссылки на Markdown-документы:

- `chapter.md` становится `chapter.html`.
- `chapter.md#section` становится `chapter.html#section`.
- `chapter.md?x=1#section` становится `chapter.html?x=1#section`.
- Вложенные относительные пути сохраняют свою структуру.

Скрипт не переписывает:

- внешние URL вроде `https://example.com/file.md`;
- protocol-relative URL вроде `//example.com/file.md`;
- `mailto:`, `tel:` и другие URL со схемой;
- якоря текущей страницы вроде `#section`;
- ссылки на ассеты, которые не заканчиваются на `.md`.

Markdown-ссылки обрабатываются через renderer rules библиотеки `markdown-it`. Raw HTML-атрибуты `href` и `src` внутри Markdown дополнительно проходят постобработку тем же правилом.

## Поведение сгенерированного HTML

- Каждая страница использует `template.html`.
- Каждая страница подключает `main.css`, `nav.css` и `article.css`.
- Каждая страница подключает локальный `publication.js` без внешних CDN-зависимостей.
- Тема сохраняется в `localStorage` под ключом `kasina-theme`.
- Режим отображения текста сохраняется в `localStorage` под ключом `kasina-content-mode`.
- На `index.html` переключатель режима чтения остается в навигации, но не меняет отображение титульной страницы.
- На mobile навигация скрыта под кнопкой-«бутербродом» и выезжает справа.

## Режимы отображения текста

Публикация поддерживает три режима:

- `bilingual`: режим по умолчанию. Видны оригинальный текст и перевод в цитатах. Перевод сохраняет оформление blockquote.
- `translation`: виден только перевод. Оформление blockquote сбрасывается, чтобы переведенные предложения выглядели как обычный текст.
- `original`: виден только оригинал.

Режимы предполагают, что перевод в Markdown размечен через `>` и после конвертации находится в `blockquote`. Генератор связывает соседние блоки оригинала и перевода без дублирования текста: оригинальный блок получает `lang="en"`, перевод получает `lang="ru"` на `blockquote`, а лишний внутренний `<p>` у переводов-предложений убирается.

## Ограничения безопасности

Перед удалением папки результата скрипт запрещает:

- использовать корень файловой системы как output;
- использовать одну и ту же папку как source и output;
- использовать родительскую папку source как output;
- использовать вложенную внутрь source папку как output.

Эти проверки нужны, потому что output удаляется перед каждой сборкой.

## Рабочий процесс

- После каждого изменения проекта нужно сразу запускать пересборку командой:

```bash
npm run build the-fire-kasina-markdown
```

- Команда запускается без дополнительного запроса подтверждения.
- Если сборка завершается ошибкой, ошибку нужно исправить или явно зафиксировать как блокер текущего изменения.
